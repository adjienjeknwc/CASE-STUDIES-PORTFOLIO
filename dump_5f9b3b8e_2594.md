Fix the Business Flow of the Life Insurance Agent Portal
The current application does not follow the real business workflow of a life insurance company. Please redesign the navigation and user flow so that every module follows the correct insurance process.
Current Issue
Currently, clicking Submit Quote directly opens the Underwriter page.
This is incorrect.
A quote is only a premium estimate. An underwriter never receives a quote. The underwriter only reviews a completed insurance proposal after the customer has accepted the quote and all required information and documents have been submitted.

Correct Navigation Rules
The application should enforce these transitions:
Lead → Customer
Customer → Quote
Quote → Customer Acceptance
Customer Acceptance → Proposal
Proposal → Documents
Documents → Review
Review → Submit Proposal
Submitted Proposal → Underwriting
Underwriting Approved → Payment
Payment Successful → Policy Issuance
The user should not be able to skip steps.
Dynamic Behaviour
Every module should update automatically.
For example:
When a proposal is submitted, it appears in the Proposal Tracking page.
When underwriting approves it, the Payment page becomes available.
After payment, the policy is created automatically.
Dashboard statistics should update in real time.
All modules should be connected through the same customer record instead of using isolated pages or dummy data.
The goal is to make the application behave like a real enterprise life insurance CRM, where each step naturally leads to the next, rather than simply linking pages together.
