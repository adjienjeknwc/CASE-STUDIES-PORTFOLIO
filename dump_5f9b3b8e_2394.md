Life Insurance Agent Portal - Business Workflow
This is a role-based Life Insurance Agent Portal. Every agent has their own customers, leads, quotes, and issued policies. Data should never be shared between agents.
Core Business Flow
Agent Login
      ↓
Dashboard
      ↓
View Assigned Leads
      ↓
Select Existing Lead OR Add New Lead
      ↓
Create Customer Profile
      ↓
Perform Needs Analysis
      ↓
Recommend Suitable Insurance Plan
      ↓
Generate Premium Quote
      ↓
Customer Accepts Quote
      ↓
Fill Proposal Form
      ↓
Upload Required Documents
      ↓
Submit Proposal
      ↓
Wait for Underwriting Decision
      ↓
If Approved
      ↓
Collect Premium Payment
      ↓
Issue Policy
      ↓
Policy becomes Active
      ↓
Agent Dashboard Updates Automatically
Application Behaviour
1. Authentication
Every agent logs in using their credentials.
After login:
Only that agent's customers should be visible.
Only that agent's leads should appear.
Policies belong only to that agent.
Quotes belong only to that agent.
Dashboard numbers are calculated from that agent's data only.
No dummy or shared data.
2. Dashboard
The dashboard is dynamic.
It automatically calculates
Total Leads
Customers
Quotes Generated
Pending Underwriting
Active Policies
Monthly Sales
Total Premium
Clicking any card opens its corresponding module.
3. Lead Management
The agent can
Create a new lead
Edit lead
Delete lead
Search leads
Filter leads
Each lead has a lifecycle.
New Lead

↓

Contacted

↓

Interested

↓

Customer Profile Created

↓

Quote Generated

↓

Proposal Submitted

↓

Policy Issued
The status changes automatically as the workflow progresses.
4. Customer Profile
Once a lead becomes interested,
Create a customer record.
Store
Personal Information
Contact Details
Occupation
Income
Nominee
Medical Information
The customer profile becomes the source of truth for every future step.
The same information should automatically populate the quote and proposal forms to avoid duplicate data entry.
5. Needs Analysis
The agent asks basic financial questions.
Example
Annual Income
Family Members
Existing Insurance
Financial Goal
Desired Coverage
Based on these answers, recommend appropriate plans.
The recommendation should be data-driven rather than a static list.
6. Quote Generation
The agent selects
Insurance Plan
Sum Assured
Policy Term
Premium Frequency
Riders
The application calculates
Premium
Taxes
Total Payable
The generated quote is saved and linked to the customer.
A customer can have multiple quotes before choosing one.
7. Proposal Form
When the customer accepts a quote,
Convert the quote into a proposal.
Most information should already be prefilled from the customer profile and selected quote.
The agent only completes any remaining required fields.
8. Document Upload
The proposal cannot be submitted until all mandatory documents are uploaded.
Examples
PAN
Aadhaar
Address Proof
Income Proof
Photograph
Display document status such as:
Uploaded
Missing
Pending Verification
9. Underwriting
After submission,
The proposal enters underwriting.
Possible statuses:
Pending

↓

Under Review

↓

Approved

OR

Rejected
The agent cannot issue a policy while underwriting is pending.
If rejected,
Show the rejection reason and allow editing and resubmission.
10. Policy Issuance
Only approved proposals can be issued.
When the agent clicks Issue Policy:
The system should automatically:
Generate a unique Policy Number
Change proposal status to Issued
Create an Active Policy record
Move the customer from Prospect to Policyholder
Update dashboard statistics
Store the issued policy in the Policies module
Data Relationships
The application should maintain these relationships:
Agent
   │
   ├── Leads
   │
   ├── Customers
   │      │
   │      ├── Quotes
   │      │
   │      ├── Proposal
   │      │
   │      └── Policy
Everything should be linked through IDs, not duplicated.
Expected Behaviour
Every action updates the database immediately.
Dashboard values refresh automatically.
Statuses change automatically as the workflow progresses.
Forms are prefilled whenever possible.
A customer can have multiple quotes but only one issued policy per accepted proposal.
Navigation follows the business process rather than allowing users to jump randomly between steps.
The application should feel like a real insurance CRM where each module is connected and reflects changes made in previous steps.
